Field guide · vibe-coding prep

How artifacts show up
on website, Linux app, and Windows app

Same published page, three different display cases. This is a working comparison — assembled from a live session plus public bug reports — for a class on what "vibe-coding" tooling actually looks like outside one browser tab.

Compiled Oct 2026 Surfaces claude.ai · Claude Desktop (Linux) · Claude Desktop (Windows) · mobile Confidence mixed — see methodology
01

The part that doesn't change

An artifact is one HTML page, built once and served from the same URL to everyone. It runs inside a locked-down frame — no print dialog, no arbitrary network calls, no reading the clipboard — and that sandbox is identical on every platform. What differs is the case it's displayed in: the side panel, the window chrome, whether the panel opens automatically, and whether the host app has finished wiring up its own artifact viewer yet.

That second part — the display case — is still being actively rebuilt as of this writing, which is exactly why the three surfaces don't behave identically yet.

Field notes — specific reports

A

macOS desktop: preview panel stays empty unresolved, single report

An HTML artifact generates normally in chat, but the right-side preview panel never opens in the macOS desktop app — the same request renders fine at claude.ai. Filed mid-2026, no maintainer reply at time of writing.

↳ claudeissues.com #78065
B

macOS desktop: Artifacts sidebar never syncs closed, not planned

A related report: the Artifacts tab in the desktop sidebar stays empty even though the same items list correctly at claude.ai/artifacts. Closed without a fix.

↳ claudeissues.com #78095
C

Mobile app: Claude Code artifacts don't appear reported gap

Artifacts published from a Claude Code session show up on web and desktop but not in the mobile app, per user reports. This matches the broader pattern: mobile is consistently the surface furthest behind.

↳ claudeissues.com #78792
D

Launch time and memory: browser vs. desktop app secondary source

One third-party guide clocks the browser at roughly 10–12 seconds to a usable chat, 1.2–2.0+ GB of memory (counting the tab), versus about 3 seconds and 180–250 MB for the native desktop app. Treat these as one blogger's numbers, not a benchmark — but they're the kind of difference a class demo will actually show.

↳ ai.zenken.co.jp desktop guide
